**Milestone 1 — in-memory B+tree** (concept, 4 sentences): a B+tree keeps all values in leaves; interior nodes only route searches. Each node holds up to `MAX_ENTRIES` (16 here, small so splits happen early in tests). When a leaf overflows it splits at its middle key and pushes that key up into the parent; a root split creates a new root, which is how the tree grows. Leaves are linked via a `next` pointer so `scan()` walks them like a linked list.

Your task, in this order:

1. `get(tree, key)` — descend to a leaf (at an interior node, go into the first kid whose separator is `> key`), then binary-search the leaf's `keys`. Return the value or `null`.
2. `insert(tree, key, val)` — descend to the leaf, insert in sorted position (or overwrite). If the leaf now exceeds `MAX_ENTRIES`, split it: middle key goes up, right half becomes a new node, fix the `next` links. Recursion returns `{ sepKey, right }` to the parent; a split at the root makes a new root and bumps `tree.height`.
3. `scan(tree)` — find the leftmost leaf, then follow `next` pointers, yielding `[key, val]` pairs.

Run `npm test` after each function. The 10k-key test is the real gate: it verifies every get round-trips, the scan is fully sorted, and `tree.height > 1` (proof your splits actually fire). When all 7 pass, we move to M2: turning those JS objects into 4KB pages on disk.
